# deploy-ssh-keys

Набор утилит для macOS для управления SSH-доступом к хостам в локальной сети:

- **`deploy_keys_macos.sh`** — интерактивная рассылка публичного SSH-ключа по хостам, чтобы подключаться без пароля. Плюс аудит, удаление и отзыв ключей.
- **`clean_known_hosts_macos.sh`** — очистка `~/.ssh/known_hosts` от неактуальных записей (проверяет доступность каждого хоста и удаляет мёртвые).

## Зачем это нужно

Если у вас дома или в небольшой сети есть несколько хостов (Mac mini, NAS, Raspberry Pi, серверы), рано или поздно возникают две задачи:

1. **Раскладывать SSH-ключ по хостам**, чтобы не вводить пароль каждый раз.
2. **Чистить `known_hosts`**, когда какие-то хосты переехали, сменили ключи или перестали существовать — иначе SSH ругается на «REMOTE HOST IDENTIFICATION HAS CHANGED» и мешает подключаться.

Оба скрипта решают эти задачи интерактивно и с цветным интерфейсом.

## 🚀 `deploy_keys_macos.sh` — рассылка SSH-ключа

### Возможности

- 📋 Выбор источника хостов: `/etc/hosts`, свой файл, ручной ввод
- 🔑 Генерация нового SSH-ключа (ed25519 или RSA 4096)
- 🎯 Выбор существующего ключа из `~/.ssh/`
- 📡 Копирование ключа через `ssh-copy-id`
- ✅ Проверка, работает ли ключ уже сейчас — чтобы не дублировать
- 📊 Реестр разложенных ключей с отпечатками в `~/.ssh/deploy_keys.log`
- 🔍 Аудит ключей: тип, отпечаток, дата, безопасность
- 🗑️ Удаление локального ключа с бэкапом
- 🚫 Отзыв ключа с удалённых хостов (удаление из `authorized_keys`)

### Использование

```bash
./deploy_keys_macos.sh
```

Открывается интерактивное меню. Типичный сценарий:

1. Если ключа нет — `4` → `2` (сгенерировать `ed25519`).
2. Если ключ есть — `1` (хосты из `/etc/hosts`).
3. Выбрать хост из списка или `a` — обработать все.
4. Ввести логин на удалённом хосте (`admin`, `root`, `igor` и т.п.).
5. Ввести пароль один раз — для `ssh-copy-id`.
6. Готово. Следующий вход — уже без пароля.

### Опции командной строки

```
./deploy_keys_macos.sh [-k FILE] [-u USER] [-t SEC] [-h]

  -k FILE    путь к публичному ключу
  -u USER    пользователь по умолчанию (для всех хостов)
  -t SEC     таймаут SSH-подключения (по умолчанию 5)
  -h         справка
```

### Формат файла со списком хостов

```
# Просто имена хостов
server1
server2.local

# Как /etc/hosts — IP и имя
192.168.1.10  server1
192.168.1.11  server2

# Просто IP
10.0.0.5
```

## 🧹 `clean_known_hosts_macos.sh` — очистка known_hosts

### Что делает

- Читает `~/.ssh/known_hosts` строка за строкой.
- Для каждой записи пытается получить ключ хоста через `ssh-keyscan` с таймаутом.
- Если хост отвечает — запись сохраняется.
- Если не отвечает — запись удаляется.
- Хешированные записи (начинаются с `|1|`) пропускаются: из них нельзя извлечь имя хоста.
- Перед изменением создаёт бэкап `known_hosts.bak.<timestamp>`.

### Использование

```bash
# Обычный запуск — с изменениями
./clean_known_hosts_macos.sh

# Сначала посмотреть, что будет удалено (без изменений)
./clean_known_hosts_macos.sh -n

# Изменить таймаут (по умолчанию 3 секунды)
./clean_known_hosts_macos.sh -t 5

# Указать другой файл
./clean_known_hosts_macos.sh -f ~/backup/known_hosts
```

### Опции

```
./clean_known_hosts_macos.sh [-n] [-t SEC] [-f FILE] [-h]

  -n         dry-run: только показать, что будет удалено, без изменений
  -t SEC     таймаут проверки хоста в секундах (по умолчанию 3)
  -f FILE    путь к known_hosts (по умолчанию ~/.ssh/known_hosts)
  -h         справка
```

### Ограничения

- **Хешированные записи** (`HashKnownHosts yes` в `~/.ssh/config`) не разбираются — из них нельзя извлечь имя хоста. Они остаются в файле.
- **Хост может быть жив, но SSH отключён** (порт 22 закрыт файрволом) — тогда запись будет удалена, хотя сервер работает. Учитывайте это, если есть сервисы с ограничениями по IP.
- **Формат `[host]:port`** поддерживается — скрипт корректно проверяет нестандартный порт.

## Требования

- macOS (тестировалось на macOS Sonoma и Sequoia)
- Встроенный `bash` 3.2+
- `ssh-copy-id`, `ssh-keyscan`, `ssh-keygen` — входят в системный OpenSSH

## Безопасность

**`deploy_keys_macos.sh`:**

- Все изменения — только с подтверждением.
- Удаление ключей — с бэкапом в `~/.ssh/key_backup_<timestamp>/`.
- Отзыв с удалённых хостов идёт **по отпечатку**, а не по комментарию — исключает удаление чужого ключа.
- Пароли не сохраняются: `ssh-copy-id` спрашивает их интерактивно.

**`clean_known_hosts_macos.sh`:**

- Перед изменением создаётся резервная копия `known_hosts.bak.<timestamp>`.
- Есть режим `-n` (dry-run), чтобы сначала посмотреть, что будет удалено.
- Хешированные записи не трогаются.

## Ограничения

- **Только macOS** — используются BSD-утилиты (`stat -f`, BSD `sed`) и bash 3.2. Для Linux часть команд нужно адаптировать.
- **Первый вход по паролю обязателен** — если ключа на хосте ещё нет, `ssh-copy-id` должен как-то авторизоваться.
- **Отзыв работает только по реестру** — если ключ раскладывался вне скрипта, отзыв его не найдёт.
