# deploy-ssh-keys

Интерактивный скрипт для macOS, который помогает раскладывать публичный SSH-ключ по хостам — чтобы подключаться к ним без пароля. Плюс управление ключами: аудит, удаление, отзыв с удалённых машин.

## Зачем это нужно

Если у вас дома или в небольшой сети есть несколько хостов (Mac mini, NAS, Raspberry Pi, серверы в локальной сети), каждый раз при подключении к новому хосту приходится вводить пароль. `ssh-copy-id` решает задачу, но запускать его вручную по каждому хосту неудобно.

Этот скрипт делает всё то же самое, но:

- **интерактивно** — меню, выбор хоста, ввод логина;
- **с учётом `/etc/hosts`** — берёт хосты оттуда, не нужно ничего перечислять вручную;
- **с проверкой** — сначала пробует подключиться по ключу, и если он уже работает, копировать не станет;
- **с реестром** — ведёт `~/.ssh/deploy_keys.log`, где видно, куда и под каким пользователем разложен ключ;
- **с аудитом ключей** — показывает, какие ключи есть в `~/.ssh/`, их отпечатки, тип, безопасность;
- **с отзывом** — умеет удалять ключ из `authorized_keys` на удалённых хостах по отпечатку.

## Возможности

- 📋 Выбор источника хостов: `/etc/hosts`, свой файл, ручной ввод
- 🔑 Генерация нового SSH-ключа (ed25519 или RSA 4096)
- 🎯 Выбор существующего ключа из `~/.ssh/`
- 📡 Копирование ключа через `ssh-copy-id`
- ✅ Проверка, работает ли ключ уже сейчас — чтобы не дублировать
- 📊 Реестр разложенных ключей с отпечатками
- 🔍 Аудит ключей: тип, отпечаток, дата, безопасность
- 🗑️ Удаление локального ключа с бэкапом
- 🚫 Отзыв ключа с удалённых хостов (удаление из `authorized_keys`)
- 🎨 Цветной интерфейс

## Требования

- macOS (тестировалось на macOS Sonoma и Sequoia)
- Встроенный `bash` 3.2 или новее (в macOS он и так есть)
- `ssh-copy-id` — входит в системный OpenSSH, но если у вас его нет, установите через Homebrew:
  ```bash
  brew install openssh
  ```

## Использование

Запустите без аргументов — откроется интерактивное меню:

```bash
./deploy_keys_macos.sh
```

```
╔══════════════════════════════════════════╗
║  Интерактивная рассылка SSH-ключа        ║
╚══════════════════════════════════════════╝
  Ключ:   /Users/igor/.ssh/id_ed25519.pub
  Реестр: /Users/igor/.ssh/deploy_keys.log
──────────────────────────────────────────

  1) Хосты из /etc/hosts
  2) Хосты из своего файла
  3) Ввести хост вручную
  4) Управление SSH-ключом
  5) Показать реестр
  6) Показать итоги этой сессии
  0) Выход

Ваш выбор:
```

### Типичный сценарий

1. Запустить скрипт.
2. Если ключа нет — `4` → `2` (сгенерировать `ed25519`).
3. Если ключ есть — `1` (хосты из `/etc/hosts`).
4. Выбрать хост из списка или `a` — обработать все.
5. Ввести логин на удалённом хосте (`admin`, `root`, `igor` и т.п.).
6. Ввести пароль один раз — для `ssh-copy-id`.
7. Готово. Следующий вход — уже без пароля.

### Опции командной строки

```
./deploy_keys_macos.sh [-k FILE] [-u USER] [-t SEC] [-h]

  -k FILE    путь к публичному ключу
  -u USER    пользователь по умолчанию (для всех хостов)
  -t SEC     таймаут SSH-подключения в секундах (по умолчанию 5)
  -h         справка
```

## Формат файла со списком хостов

Если используете пункт `2` (свой файл), поддерживаются такие варианты:

```
# Просто имена хостов
server1
server2.local

# Как /etc/hosts — IP и имя
192.168.1.10  server1
192.168.1.11  server2

# Просто IP
10.0.0.5
```

Строки, начинающиеся с `#`, игнорируются.

## Реестр

Все успешные операции записываются в `~/.ssh/deploy_keys.log` в формате:

```
host user added 2026-09-15 14:30:00 fp=SHA256:akRodw0f+LWX91jmHyAbcZ/hjlAkNjfS7EYNYDnbEeQ
```

Это позволяет:

- видеть, куда и под каким пользователем разложен ключ;
- проверять, работает ли ключ, не подключаясь заново;
- отзывать ключ с хостов по отпечатку.

Сбросить реестр: `rm ~/.ssh/deploy_keys.log`

## Безопасность

- Все изменения — только с подтверждением.
- Удаление ключей — с бэкапом в `~/.ssh/key_backup_<timestamp>/`.
- Отзыв с удалённых хостов идёт **по отпечатку**, а не по комментарию — это исключает удаление чужого ключа.
- Пароли не сохраняются: `ssh-copy-id` спрашивает их в интерактивном режиме.

**Важно:** скрипт не заменяет проверку ключа хоста. Первое подключение к новому хосту (первое копирование) делается с `StrictHostKeyChecking=no`, потому что `ssh-copy-id` должен как-то аутентифицироваться. Если для вас это критично — подключайтесь к хосту предварительно вручную, чтобы ключ хоста попал в `known_hosts`, а потом запускайте скрипт.

## Ограничения

- **Работает только на macOS** — использует `stat -f`, BSD-`sed` и рассчитан на bash 3.2. Для Linux логика та же, но часть команд нужно адаптировать.
- **Первый вход по паролю обязателен** — если ключа на хосте ещё нет, `ssh-copy-id` должен как-то авторизоваться. Никакой скрипт это не обойдёт без заранее настроенного доступа.
- **Отзыв работает только по реестру** — если ключ раскладывался вне скрипта, отзыв его не найдёт.
- **Хешированные записи в `known_hosts`** не разбираются — за это отвечает отдельный скрипт (см. «Связанные проекты»).

## Связанные проекты

Если у вас накопился мусор в `~/.ssh/known_hosts`, может пригодиться скрипт для его очистки от неактуальных записей — он проверяет доступность каждого хоста и удаляет мёртвые записи.
